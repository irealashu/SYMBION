Status: Draft

# 1. Introduction

SYMBION is a language optimized for human-AI co-thinking.

Natural languages are optimized for communication.

Programming languages are optimized for machine execution.

SYMBION is optimized for reasoning.

The language provides a structured way to express:

- Claims
- Confidence
- Evidence
- Relationships
- Ambiguities
- Perspectives
- Goals

in a syntax that is both human-readable and machine-parsable.

---

# 2. Core Principles

SYMBION follows three foundational principles:

## Principle 1: Everything is a Statement

Every reasoning element is represented as a statement.

Example:

```symbion
renewable energy
```

---

## Principle 2: Statements Form Trees

Reasoning is represented as a hierarchy.

Child nodes add:

- support
- explanation
- consequences
- alternatives
- objections

to a parent node.

Example:

```symbion
renewable energy
    => lower emissions
        => slower climate change
```

---

## Principle 3: Uncertainty Must Be Explicit

Whenever possible, confidence should be declared.

Example:

```symbion
+ renewable energy reduces emissions
```

---

# 3. Indentation Rules

SYMBION is indentation-based.

Indentation defines hierarchy.

## Rules

- Four spaces per level.
- Tabs are not allowed.
- Mixed indentation is invalid.
- Child statements belong to the nearest less-indented parent.
- Statements at the same level are siblings.

Example:

```symbion
Goal: reduce traffic

remote work
    => fewer commutes

public transit
    => fewer cars
```

Tree:

```text
Goal: reduce traffic
├── remote work
│   └── fewer commutes
└── public transit
    └── fewer cars
```

# 4. Statement Syntax

Basic form:

```symbion
statement
```

Examples:

```symbion
renewable energy

public transport
```

---

# 5. Confidence Markers

A statement may begin with a confidence marker.

## Syntax

```symbion
++ statement
+ statement
~ statement
- statement
-- statement
```

## Definitions

| Marker | Meaning |
|----------|----------|
| ++ | Strongly supported |
| + | Likely |
| ~ | Uncertain |
| - | Unlikely |
| -- | Rejected |

## Example

```symbion
++ earth orbits sun
+ solar energy scales
~ fusion power by 2035
- perpetual motion machine
-- flat earth model
```

---

# 6. Evidence Tags

Evidence tags indicate how a claim is supported.

## Syntax

```symbion
statement @TAG
```

## Tags

| Tag | Meaning |
|-------|---------|
| @E | Empirical evidence |
| @L | Logical reasoning |
| @H | Historical observation |
| @I | Intuition |
| @S | Simulation |

## Example

```symbion
+ remote work boosts productivity @E

+ democracy adapts over time @H

+ mathematical proof valid @L
```

# 7. Relationships

Relationships connect one idea to another.

## Supported Relationships

### Causes

```symbion
=> 
```

Meaning:

```text
causes
```

Example:

```symbion
greenhouse gases
    => global warming
```

---

### Caused By

```symbion
<=
```

Meaning:

```text
caused by
```

Example:

```symbion
flooding
    <= heavy rainfall
```

---

### Enables

```symbion
>>
```

Meaning:

```text
enables
```

Example:

```symbion
education
    >> innovation
```

---

### Correlates

```symbion
<>
```

Meaning:

```text
correlates with
```

Example:

```symbion
ice cream sales
    <> summer temperatures
```

---

### Conflicts

```symbion
!=
```

Meaning:

```text
conflicts with
```

Example:

```symbion
induced demand
    != more roads reduce congestion
```

# 8. Goals

Reasoning sessions may begin with goals.

## Syntax

```symbion
Goal: description
```

## Example

```symbion
Goal: reduce traffic congestion
```

Goals serve as root nodes.

---

# 9. Ambiguity Operator

The ambiguity operator identifies unresolved concepts.

## Syntax

```symbion
concept ?
```

or

```symbion
concept ? interpretation1 ? interpretation2
```

## Example

```symbion
success ? wealth ? happiness ? influence
```

Meaning:

The term "success" has unresolved meanings.

---

# 10. Reasoning Commands

Commands are requests made by a thinker or AI.

Commands are written in uppercase.

## Supported Commands

```symbion
EXPAND
COMPRESS
CHALLENGE
SIMULATE
ABSTRACT
INVERT
MERGE
```

---

## EXPAND

Generate sub-ideas.

```symbion
EXPAND renewable energy
```

---

## COMPRESS

Create a concise summary.

```symbion
COMPRESS discussion
```

---

## CHALLENGE

Expose assumptions.

```symbion
CHALLENGE strategy
```

---

## SIMULATE

Predict outcomes.

```symbion
SIMULATE universal basic income
```

---

## ABSTRACT

Find higher-level patterns.

```symbion
ABSTRACT transportation systems
```

---

## INVERT

Explore opposite assumptions.

```symbion
INVERT remote work improves productivity
```

---

## MERGE

Combine ideas.

```symbion
MERGE renewable energy + grid storage
```

---

# 11. Perspective Blocks

Perspective blocks allow multiple viewpoints.

## Syntax

```symbion
<perspective>
...
</perspective>
```

## Example

```symbion
<citizen>
public transport = convenience
</citizen>

<government>
public transport = infrastructure
</government>

<environment>
public transport = emission reduction
</environment>
```

---

# 12. Memory Blocks

Reusable knowledge may be stored in memory blocks.

## Syntax

```symbion
MEM{
...
}
```

## Example

```symbion
MEM{
Earth radius = 6371km
Speed of light = 299792458m/s
}
```

---

# 13. Comments

Comments begin with '#'.

Example:

```symbion
# Climate discussion

+ renewable energy @E
```

Comments are ignored by parsers.

---

# 14. Parser Requirements

A compliant parser shall:

- Validate indentation.
- Parse confidence markers.
- Parse evidence tags.
- Parse relationship nodes.
- Parse perspective blocks.
- Parse memory blocks.
- Preserve hierarchical structure.
- Export a reasoning tree.

Preferred export format:

```json
{
  "type": "statement",
  "confidence": "+",
  "text": "renewable energy",
  "evidence": ["E"],
  "children": []
}
```
